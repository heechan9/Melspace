# MelSpace

> 가칭 Space Telemetry Lab. 공개 NASA 우주선 텔레메트리로 이상 구간 탐지 방법을 비교하는 학습형 프로젝트.

> **상태: 기획 단계 · 구현 및 실험 미실행**
> 이 저장소에는 아직 코드, 데이터, 실행 결과가 없습니다. 아래 수치는 모두 **원 연구(Hundman et al., 2018)가 공개한 값**이며, 이 프로젝트가 새로 실행한 결과가 아닙니다.

공개된 NASA 우주선 텔레메트리 시계열(SMAP 위성·MSL 큐리오시티 로버)에서 **이상 구간을 탐지하고, 탐지 방법별 결과를 같은 기준으로 비교**하는 작은 학습형 프로젝트입니다.

**이 프로젝트가 아닌 것:** 실제 우주선 제어 시스템, 고장 원인 진단 도구, 실시간 운용·감시 시스템이 아닙니다. 익명화된 공개 데이터로 오프라인 실험만 합니다.

## 2. 데이터 (확인한 내용)

| 항목 | 확인 결과 | 출처 |
|---|---|---|
| 구성 | SMAP 55채널·MSL 27채널, 라벨된 이상 구간 105개 | telemanom README |
| 파일 형식 | 채널마다 `train/<id>.npy`, `test/<id>.npy`, 형태 `(시점 수, 입력 차원)` | telemanom README |
| 텔레메트리 값 위치 | **첫 번째 열**. 나머지 열은 명령 송수신 여부를 one-hot으로 인코딩한 정보 | telemanom README · `channel.py` |
| 이미 적용된 전처리 | 시간 정보 익명화, 값은 **test 구간의 최솟값·최댓값 기준으로 (-1, 1) 스케일링** 완료 | telemanom README |
| 채널 의미 | 채널 ID 익명화. 첫 글자가 유형을 뜻함(README 예: `P`=power, `R`=radiation) | telemanom README |
| 라벨 | `labeled_anomalies.csv`: `chan_id`, `spacecraft`, `anomaly_sequences`(test 인덱스 기준 시작·끝), `class`(point/contextual), `num_values` | 원본 CSV 직접 확인 |
| 현재 배포 경로 | Kaggle `patrickfleith/nasa-anomaly-detection-dataset-smap-msl` (약 272 MB, 2022-10-16 v1, 사전학습 모델·예측값 포함) | Kaggle 메타데이터 · telemanom README |

**지키는 규칙**
- 익명 채널에 실제 센서 이름·단위·시각을 붙이지 않습니다. 시간은 "시점 인덱스"로만 표기합니다.
- `P`, `R` 외 첫 글자의 의미는 원 자료에서 확인하지 못했으므로 추측하지 않습니다.
- 원본 데이터 파일은 저장소에 커밋하지 않고, 다운로드 방법만 안내합니다(이용 조건은 아래 4절).

**평가상 한계 (데이터에서 이미 정해진 것)**
- 스케일링에 test 구간의 최솟값·최댓값이 쓰였습니다. 즉 test 정보가 값의 범위에 이미 반영돼 있어, 고정 절댓값 임계값의 성능은 다소 낙관적일 수 있습니다.
- train 구간이 이상 없는 정상 구간인지는 README에서 명시적으로 확인하지 못했습니다. 첫 세션에서 확인할 항목으로 둡니다.
- 라벨 CSV에서 `P-2` 채널이 서로 다른 구간으로 **두 번** 등장합니다. 로드 단계에서 처리 규칙(병합 여부)을 정하고 기록합니다.

## 3. 평가 기준 (초안)

원 연구 코드(`detector.py`)의 구간 단위 판정 방식을 기준으로 삼고, 탐지 지연을 추가로 정의합니다.

| 지표 | 계산 기준 |
|---|---|
| 포착(TP) | 실제 이상 구간 하나와 **한 시점이라도 겹치는** 탐지 구간이 있으면, 그 실제 구간을 1회 포착으로 셉니다(실제 구간당 최대 1회). |
| 오경보(FP) | 어떤 실제 이상 구간과도 겹치지 않는 탐지 구간 1개당 1회 |
| 놓침(FN) | 겹치는 탐지 구간이 하나도 없는 실제 이상 구간 |
| 이상 포착률(Recall) | TP / (TP + FN) |
| 정밀도(Precision) | TP / (TP + FP) |
| 탐지 지연 | 포착된 실제 구간마다 `max(0, 첫 겹침 탐지 시점 − 실제 시작 시점)`, **시점 인덱스 단위** (초·분으로 환산하지 않음) |

**데이터 분할 원칙**
- `train` → 정상 패턴 통계 학습
- `train`의 **마지막 일부(시간순)** → 임계값·파라미터 선택용 검증 구간
- `test` + 라벨 → **최종 평가에만** 사용. test 정답으로 임계값을 맞추지 않습니다.
- 참고: 원 연구의 동적 임계값은 라벨을 쓰지 않지만 test 오차 분포 자체로 임계값을 정합니다. 이 프로젝트의 기준선과 방식이 다르므로 수치를 직접 비교하지 않습니다.

## 5. 원 연구가 공개한 결과 (이 프로젝트의 결과 아님)

telemanom README에 따르면 기본 설정의 LSTM + 동적 임계값은 전체 기준 정밀도 87.5%, 재현율 80.0%를 보고했습니다. 이 프로젝트는 이 수치를 재현하거나 넘어서는 것을 목표로 하지 않습니다.

## 6. 개발 순서

[위키독스 실습](https://wikidocs.net/300834)의 데이터 준비 → 전처리 → 모델 → 평가 → 시각화 흐름을 시계열 이상탐지에 맞춰 적용합니다(이미지 분류 모델을 쓰지 않습니다).

| 단계 | 이 프로젝트에서 할 일 |
|---|---|
| 데이터 준비 | 채널 1개의 train/test `.npy`와 라벨 행 불러오기, 형태 확인 |
| 전처리 | 텔레메트리 열(첫 열)만 분리, 결측·범위·스케일 확인 |
| 모델 | 단순 기준선 하나. 1순위 후보: train 구간으로 관리한계를 고정하는 개별값 관리도(FabGuard `spc.py` 방식). 딥러닝은 필수 아님 |
| 평가 | 3절 기준의 구간 단위 TP/FP/FN, 포착률, 탐지 지연 |
| 시각화 | 시계열 + 실제 이상 구간 음영 + 탐지 구간 표시 |

**작업 방식:** 한 번에 작은 기능 하나, 핵심 조건을 바꾸기 전에 결과 예상 질문 하나, 실행 후 예상과 비교. 학습 기록은 `예상 / 변경 / 실제 결과 / 알게 된 점`으로 남깁니다.

## 7. 다음 개발 세션 첫 과제

**센서 채널 하나를 불러와 그래프로 확인하기**

1. 데이터 받는 방법 결정 (Kaggle 계정·API 키 사용 여부)
2. 채널 하나 선택 (라벨 CSV에서 이상 구간 수·유형을 보고 함께 고름)
3. train/test `.npy`의 형태와 첫 열 값 범위 확인
4. 첫 열을 선 그래프로 그리고, 라벨된 이상 구간을 음영으로 표시
5. 학습 기록 1건 작성
