## 1. 평가 기준 (초안)

원 연구 코드(`detector.py`)의 구간 단위 판정을 참고하되, **다중 사건 매칭 규칙이 원 코드와 다릅니다**(아래 표 마지막 두 행). 탐지 지연은 새로 정의합니다.

| 지표 | 계산 기준 |
|---|---|
| 포착(TP) | 실제 이상 구간 하나와 **한 시점이라도 겹치는** 탐지 구간이 있으면, 그 실제 구간을 1회 포착으로 셉니다(실제 구간당 최대 1회). |
| 오경보(FP) | 어떤 실제 이상 구간과도 겹치지 않는 탐지 구간 1개당 1회 |
| 놓침(FN) | 겹치는 탐지 구간이 하나도 없는 실제 이상 구간 |
| 이상 포착률(Recall) | TP / (TP + FN) |
| 정밀도(Precision) | TP / (TP + FP) |
| 탐지 지연 | 포착된 실제 구간마다 `max(0, 첫 겹침 탐지 시점 − 실제 시작 시점)`, **시점 인덱스 단위** (초·분으로 환산하지 않음) |
| 원 코드와의 차이 | 탐지 구간 하나가 실제 구간 여러 개와 겹치면, telemanom 원 코드는 **그 경보로는 첫 번째 실제 구간만** 포착(TP)으로 기록하고, 나머지 실제 구간은 다른 경보로 매칭되지 않으면 놓침(FN)이 됩니다. MelSpace 규칙은 겹친 실제 구간을 모두 포착으로 셉니다. 예: 긴 경보 하나가 실제 구간 2개를 덮으면 원 코드 TP 1·FN 1, MelSpace TP 2·FN 0. 그래서 **두 규칙의 결과를 함께** 보고하고, 시점 단위 정밀도·재현율도 같이 보고합니다. |
| 판정 보류 | 기준 구간 안에 한계 밖 값이 있어 관리도가 이후 판정을 보류하면(`baseline_review_required`), 그 실행은 **평가 불가**로 표시합니다. "이상 없음"으로 세지 않고, 포착률·오경보 집계에서 뺍니다. **전체 예정 실행 수, 평가 불가 실행 수, 제외 이유**를 함께 보고합니다. |
| 방법 간 비교 | 여러 방법을 비교할 때는 **모든 방법에서 평가 가능한 같은 채널 집합**으로만 비교합니다. 방법마다 제외된 채널이 달라 평가 대상이 서로 다른 평균은 직접 비교하지 않습니다. |

**데이터 분할 원칙**
- `train` 파일을 시간순으로 **fit / gap / validation** 세 부분으로 나눕니다.
  - `fit`: 관리한계 등 기준 통계를 **여기에만** 맞춥니다.
  - `gap`: fit과 validation 사이에 비워 두는 구간(경계 정보 누수 방지).
  - `validation`: 파라미터 선택용. 이 구간이 정상인지는 확인되지 않았으므로, 여기서 나온 탐지 비율은 "오경보율"이 아니라 **"경보율"**로 표시합니다.
- **기준 구간 규칙은 사전 고정:** fit·gap·validation의 위치와 길이는 test 그림·라벨·성능을 보기 **전에** 설정 파일로 정하고 해시로 고정합니다. test를 보고 유리한 기준 구간을 고르지 않으며, 바꿀 때는 새 설정 버전과 사유를 남깁니다.
- 기준 구간(fit)에 한계 밖 값이 없다는 것은 평가를 진행할 **최소 조건**일 뿐, 그 구간이 통계적으로 안정적이라는 증명은 아닙니다.
- `test` + 라벨 → **최종 평가에만** 사용. test 정답으로 임계값을 맞추지 않습니다.
- 참고: 원 연구의 동적 임계값은 라벨을 쓰지 않지만 test 오차 분포 자체로 임계값을 정합니다. 이 프로젝트의 기준선과 방식이 다르므로 수치를 직접 비교하지 않습니다.
