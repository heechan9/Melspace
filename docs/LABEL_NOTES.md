# 라벨 파일 탐색 기록

> 상태: **탐색 (라벨 메타데이터만)**. 센서값(`.npy`)은 train·test 모두 아직 열지 않았습니다. 탐지·평가 결과가 아닙니다.
> [README로 돌아가기](../README.md) · [데이터 문서](./DATA.md)

## 0. 열람 범위 결정 (소유자, 2026-10-14)

- 분할(fit/gap/validation)·평가 채널 선정 규칙을 고정하기 전까지는 **train 센서값과 라벨 메타데이터만** 봅니다. **test 센서값은 열지 않습니다.**
- 이유: [AGENTS.md](../AGENTS.md)의 사전 고정 ①(분할·채널 선정 규칙은 test 열람 전에 고정)을 지켜, 이후 결과를 "test를 미리 보지 않은 평가"로 보고할 수 있게 하기 위해서입니다.
- 라벨 파일은 test 구간의 **위치 정보**입니다. 아래 내용은 이미 열람한 것이므로, 채널 선정 규칙을 정할 때 이 내용을 근거로 쓰면 그 사실을 기록합니다.

## 1. 출처와 재현 방법

- 파일: `labeled_anomalies.csv` — https://raw.githubusercontent.com/khundman/telemanom/master/labeled_anomalies.csv (telemanom, Apache 2.0 저장소)
- 받은 날: 2026-10-13 (UTC). 이 저장소에는 커밋하지 않습니다.
- 집계 방식: 표준 라이브러리 `csv`로 읽고 `anomaly_sequences`를 `ast.literal_eval`로 해석. 구간 길이는 `끝 − 시작 + 1`(양 끝 포함으로 **가정**). `class` 열은 따옴표 없는 목록(`[point, contextual]`)이라 문자열로 나눠 셉니다.
- 아래 수치는 Claude가 1회 실행해 얻은 값입니다. 독립 재현은 PR 코멘트에서 따로 기록합니다.

## 3. 로드·평가 전에 정해야 할 것

1. **P-2 중복 행.** 같은 채널이 `[[5350, 6575]]`, `[[5300, 6420]]` 두 행으로 있고 두 구간이 대부분 겹칩니다(`num_values`는 둘 다 8209). 그대로 쓰면 한 사건이 두 번 세어질 수 있습니다. 병합할지, 한 행만 쓸지, 평가에서 제외할지는 **로드 규칙(핵심)**으로 소유자가 정합니다.
2. **이상 비율이 30%를 넘는 행 13개.** test의 약 34~50%가 이상 구간입니다: SMAP E-3, E-4, D-1, D-2, D-3, D-4, D-7, D-12, F-2, A-8, A-9 / MSL M-1, M-2 (모두 구간 1개). "한 시점이라도 겹치면 포착" 규칙에서는 긴 경보 하나로 쉽게 포착되므로, 채널별 결과와 시점 단위 지표를 함께 봐야 합니다. 평가 채널 선정에 이 정보를 쓸지는 소유자가 정하고 기록합니다.
3. **구간 순서가 시작점 순이 아닌 행.** P-1, E-12(SMAP), P-11(MSL). 지연·매칭 계산 전에 시작점 기준 정렬이 필요합니다.
4. **구간 양 끝 포함 여부.** CSV만으로는 끝 인덱스가 포함인지 확정할 수 없습니다. 위 길이는 포함으로 가정한 값입니다. telemanom 코드의 사용 방식을 확인해 규칙으로 정합니다.

이상 없음으로 확인한 것:
- 모든 구간의 끝이 해당 행의 `num_values`보다 작습니다.
- 행마다 `class` 개수와 구간 개수가 같습니다.

## 4. 첫 과제 채널 A-1

`SMAP`, 구간 `[[4690, 4774]]` 1개, `point`, test 길이 8640. 구간이 하나이고 짧아(85시점, 양 끝 포함 가정) 첫 그래프에서 위치를 확인하기 쉽습니다. 이 선택은 첫 과제(로드·그래프 연습)용이며, 평가 채널 선정 규칙과는 별개입니다.
